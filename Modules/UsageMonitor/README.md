# UsageMonitor

Read-only account usage and local DeepSeek spend for the horizontal strip, aligned to CodeNotch **1.20.0 / `6e8b0f8`**. No model calls, telemetry, sign-in flows, or credential refresh. Selected Codex activity is observed only to drive the upstream busy/idle refresh cadence (see below); no conversation UI, prompt/response retention or transmission. `start()` reads provider sources only after `monitoringEnabled` is persisted and only for selected providers. Hiding the strip is not disabling monitoring; the explicit monitoring switch controls reads.

## Usage strip

The existing VitaPet status menu has **Coding usage / 编程用量** → show/hide, refresh and **Usage settings / 用量设置**. No second menu-bar icon or dashboard is created. The nonactivating strip is visible by default; monitoring stays off until explicitly enabled in settings.

The strip ports CodeNotch's steady top/bottom outline, 44pt rings, design-frame spacing, typography and three surfaces: system Liquid Glass, dark glass (clear glass over a black backing), and solid black. Glass requires macOS 26+ and falls back to solid black; Reduce Transparency always uses opaque black. Older settings retain their existing sources, opt-in and placement, with system glass as the surface default.

The nonactivating panel attaches to the physical screen edge, not below the menu bar. Transparent flare pockets pass mouse events through to underlying apps; pointer routing rejects points outside the clipped strip before building its outline. The existing VitaPet menu and the trailing arc open settings; native `activeAlways` tracking wakes the gear and keeps detail buttons reachable even while VitaPet is inactive. Reading and gear transitions respect Reduce Motion. Hover details are built only when shown and release their SwiftUI content on close or removal, so hidden countdowns and charts do not keep updating; monitoring and visible-detail refresh rates are unchanged. Hardware-notch joining and drag/fold animations are not included.

**Keychain access is removed, not merely made noninteractive.** This includes startup/polling reads, settings presence probes, app-owned keys, and Cursor CLI/GitHub CLI/CodeNotch fallbacks. The credential save/remove UI and APIs are gone. Existing Keychain items are not read, migrated, changed or deleted. No replacement plaintext secret store or CLI/browser workaround is introduced. Compatible existing Pi sign-ins and the previously supported tool files are read-only, behind the existing selected-provider opt-in.

Settings control source selection/order, display, top/bottom edge, surface, horizontal position, size and background opacity. Refresh scheduling follows CodeNotch instead of a custom interval picker; legacy `refreshInterval` values are ignored without changing opt-in or other settings. Background opacity is shared by the strip and handle; text and glyphs stay opaque. Hover a provider for individual windows, reset/last-update times and errors; click its icon to refresh that source directly (details also have an accessibility action). DeepSeek instead shows today's estimated spend as a percentage of a fixed US$100 budget, drawing the same quota arc as other providers; its detail shows today / last 7 / last 30 days as the same percentages with compact scan/pricing notes and never shows amounts. Unknown spend shows `—` and no arc. Other values are consumed quota, not remaining quota: system accent normally, yellow from 50%, orange-red from 70% (CodeNotch's default bands), and `—` when unavailable. Sources without a compatible file sign-in remain disconnected instead of accessing Keychain or inventing a percentage.

Pi discovery uses an absolute (or `~/…`) `PI_CODING_AGENT_DIR`, otherwise `~/.pi/agent`, or the existing `~/.config/pi` when the default directory is absent (Finder launches do not inherit shell overrides). For network providers it reads bounded regular `auth.json` and `models.json` files; it does not load Pi/extension code. Only the exact provider IDs above are eligible. Ollama accepts `type: api_key` literal `key`, or an existing literal `models.json` provider `apiKey` when no auth entry exists. `!commands`, environment-secret references, provider-scoped environments, alternate origins and extra auth headers are rejected, including model routing overrides. Unknown/custom gateway providers are not borrowed. An existing but expired/incompatible Pi entry does **not** silently switch to a different tool account. Pi OAuth `expires` is milliseconds; refresh and all credential writes remain Pi's responsibility.

These are provider-owned endpoints, not a guarantee of a stable public quota API. Endpoint/schema/plan changes can produce `failed` or `notConnected`; unsupported data is never converted to zero. Only known quota fields are interpreted. Returned zero and values above 100% remain accurate.

## Copilot quota display

The ring prefers a metered premium quota, then chat, then completions; an unlimited/count-only row cannot hide a later percentage. Consumed quota comes from `used / entitlement`, otherwise `(100 - percent_remaining) / 100`, otherwise `(entitlement - remaining) / entitlement`. Negative remaining percentages preserve overage. A percentage-only response is usable; an explicit zero entitlement is not, even with `percent_remaining: 100`. Unlimited and token-billed placeholder responses explain the absent ring instead of inventing 0%. Counts without a denominator remain informational. No plan-based credit ceiling, browser budget lookup or new credential source is inferred. The native UI fixtures feed these parsed response shapes into the real strip and hover detail; they are not live-account verification.

## Local DeepSeek spend

`PiLocalSpend.swift` borrows the Pi-import approach from **CC Switch `5ae6ad3`**, without its proxy, database or runtime dependency. It reads only the selected local Pi session tree. Discovery: absolute/`~/…` `PI_CODING_AGENT_SESSION_DIR`, then the existing agent `settings.json`'s absolute/`~/…` `sessionDir`, then `<agent>/sessions`. Relative session paths, per-project settings, CLI-only `--session-dir` and SDK-only roots cannot be inferred by a Finder app and are not merged or guessed.

- The strip shows **today's** spend as a percentage of a fixed **US$100** budget with the usual quota arc. The detail shows today / last 7 days / last 30 days as percentages of the same budget, compact scan/record/pricing counts, and no dollar amounts. Today begins at local calendar midnight. The trailing windows end at the reading timestamp and span exactly **168 / 720 hours**; they are not truncated at a week/month boundary and do not change with the calendar's first weekday or DST. Figures are estimated **USD**, not a vendor bill or shared-wallet delta. No exchange rate is invented.
- Uses assistant messages and explicitly model-attributed `usage` entries. `responseModel` takes priority over the requested model; a DeepSeek model family is recognized even behind a gateway. Opaque aliases, other clients/machines, unrecorded calls, and unattributed tool/compaction totals are not counted. Successful, aborted and failed calls with costs remain billable records.
- Pricing order follows CC Switch: **recorded cost → model pricing → unknown**. Positive Pi totals win, then complete recorded cost components. Zero placeholders with nonzero tokens are not free. Prefer existing `models.json` rates (USD/million tokens), including tiers, partial overrides and cache-write durations. Match the actual model first; use the requested gateway ID's configuration only when its canonical family matches the actual model. Never carry a requested Pro rate onto an actual Flash/unknown response.
- If configuration has no valid rate, use the small `DeepSeekReferencePricing.swift` snapshot from CC Switch `5ae6ad3` (2026-10-08), with V4 aliases checked against [DeepSeek's public prices](https://api-docs.deepseek.com/quick_start/pricing). V4 Flash and Pro use **peak** rates, like CC Switch; they are not gateway invoices, historical tariffs or time-of-use billing. Flash: input/output/cache-read 0.30/1.20/0.006; Pro: 1.32/3.96/0.044 USD/million, cache-write 0. V3/V3.1/V3.2 retain the named snapshot rates. Namespace/case and explicitly known V4 aliases are normalized; unknown/future versions and ambiguous retired `deepseek-chat`/`deepseek-reasoner` do not inherit a price. No runtime price lookup, Pi code or secrets/commands are executed. Price changes re-estimate only missing/placeholder costs, never valid recorded fees. Pi fresh-input and output-included reasoning are not charged twice.
- Decimal arithmetic is used for accumulation. Fork/clone copies retain entry IDs and timestamps, which are deduplicated across files; reused upstream response IDs do not merge genuine requests. ID-less legacy or malformed matching records are skipped with an incomplete-scan warning, rather than hashing/retaining conversation text to guess their identity.
- Missing records/prices show `—` and an explanation, never an invented zero. Detail distinguishes no logs, no recognized DeepSeek records, and missing rates. It lists fully scanned/discovered file counts and deduplicated recorded/configured/reference-priced record counts; reference prices have a dated disclaimer. A fully scanned period with retained history but no requests in that period legitimately shows zero. Unpriced records and incomplete scans are visible warnings. Deleted logs cease contributing; this is retained-history accounting, not a permanent billing ledger.
- Reads are bounded: 4096 directory entries, 1024 files, depth 8, 64 MiB/file and per refresh, 1 MiB/line, 50,000 cached matching records. Changed files are rescanned; unchanged files use memory-only billing metadata. A scan that reached EOF is reusable even if malformed lines or an unfinished tail made its coverage incomplete: keep the warning, but do not reread an unchanged file and starve pending history. I/O failures or record-limit stops remain retryable. Files deferred by the byte budget are retried on later refreshes. Symlinks inside the tree, nonregular files, oversized records and unfinished JSONL tails are skipped and flagged. Append/rewrite/truncation/deletion invalidate the affected contribution.
- No auth/key is required, even for shared keys or gateway use. Source opt-in, cancellation and per-source refresh feedback still apply; obsolete DeepSeek network 429 backoff is ignored. No transcript/aggregate is stored on disk or sent anywhere.

## Google reachability gate

Every **network usage GET** first makes a new anonymous `GET https://www.google.com/generate_204`. This includes all three Codex endpoints, scheduled/manual/attention refreshes, and the optional same-response comparison. A previous successful probe never authorizes another request. Only HTTPS success from that exact URL with status **204** is accepted; redirects, captive-portal 200s, DNS/TLS/connection errors and timeouts fail closed. The probe has a **5-second request/resource timeout**, a separate ephemeral session, no cookies/cache/credential storage, no copied provider headers, and no result cache. Cancellation prevents the dependent provider request.

A failed probe skips that account request and explains why. Previously verified same-account readings are marked stale, not relabeled as new data. If Google becomes unavailable between the main Codex quota and optional statistics, the valid quota survives but the optional calls are skipped and the card notes Google is unreachable. The next eligible refresh tries again; no Google-specific backoff or allowlist override is added. Normal vendor 429 backoff remains intact.

**DeepSeek is exempt:** its local-cost branch runs before credentials, URLSession setup or Google checks. Disabled/unselected sources and sources with no usable login do not issue probes or account requests.

## Codex detail and refresh behavior

The Codex card ports the original shell, header, grouped quota rows, rounded used/remaining percentages, usage pace, unused reset credits, five account statistics and 30-day chart. Primary/weekly headline selection is named, never the first extra window. CodeNotch's extra-limit, weekly-headline, reset-time and pace preferences are borrowed read-only during an authorized fetch. The custom nonactivating child panel keeps the original silhouette instead of an `NSPopover` frame. For readable quota text it uses a 320pt width, 12pt body and 15pt title, independent of strip scale; quota/reset lines no longer auto-shrink below that body size. Its content is bilingual and remains live while open.

- A **15s** common-run-loop tick checks dates, not credentials. Fetch spacing is **30s while Codex is busy**, otherwise **5 minutes**.
- Looking (hovering a provider or opening the menu) shares a **15s** cooldown. Work finishing refreshes Codex only, throttled at **30s**. Wake and a quota rollover trigger a refresh; the rollover is consumed only once.
- Codex activity follows the original **2s** scan and **8s** freshness heuristic, parent/helper folding and open-rollout detection. It reads the default account's `state_5.sqlite` / `sqlite/codex-dev.db` read-only and bounded lifecycle records (at most four 256 KiB tail slices). Titles/previews are not selected. No hooks, subprocesses, permissions prompts or session UI are installed. Turning monitoring off or removing Codex stops the activity timer as well as quota requests.
- Icon clicks bypass the attention cooldown but not opt-in, selection, in-flight deduplication or provider backoff. Only that source enters `refreshing`; a single-source result holds its pressed feedback for the original **380ms**. The quota arc makes one **0.95s** turn with the original timing curve, and the ring presses to **0.93** scale. No repeat-forever spinner is used. Reduce Motion skips rotation and animated scaling; unavailable sources do not create extra network requests.
- Providers have independent in-flight tasks. The original **60s** pass deadline clears feedback and releases the scheduler without starting a duplicate read for a stuck source. Canceled predecessors are awaited per source; obsolete results cannot publish. Disable/stop clears all feedback.
- The original **15-minute** stale grace keeps recent same-account readings undimmed during a transient failure or locally detected token expiry. Expired tokens are never sent or refreshed by VitaPet. HTTP 401/403 clears the rejected account's data.
- With a successful Google check before each request, Codex queries the source for these three endpoints, including attention/manual refresh. No invented TTL or exponential retry policy is added. Optional endpoint results are not synthesized from older readings.

## Safety and persistence

- Initializers, previews and settings expansion never discover credentials. There is no Keychain reader, existence check, save/delete API, credential input field, or `SecItem`/`SecKeychain` call in production code.
- Without compatible existing Pi/tool files, network sources return `notConnected` without any network request or replacement secret file, even when retained in a user's existing selection. The selection itself is not silently changed.
- Local credential/settings files must be regular files, at most 256 KiB, opened nonblocking; SQLite is read-only, has a 200ms busy timeout, value-size and VM instruction limits. No processes are spawned.
- Requests are GET to fixed HTTPS endpoints, using ephemeral sessions with cookies/cache/credential storage disabled. Every redirect is refused, preventing cross-origin credential forwarding. Deadlines: 15s request / 20s resource; streamed response limit: 1 MiB. No raw response body or underlying error is displayed or logged.
- Reads never overlap for the same source. Changing provider membership or monitoring cancels old work; replacements await its completion. Presentation-only reordering does not reread credentials, cancel requests or reset the poll schedule. Generation checks discard late responses. `stop()` awaits cancellation; an aborted app quit restarts the same store without changing opt-in.
- 429 `Retry-After` seconds/HTTP-date is respected by polling and manual refresh, with a minimum 60s delay. Backoff is saved across restarts in `usage-monitor.json` beside settings; no tokens or account bodies are persisted. If that write fails, in-memory backoff remains active and `settingsError` reports the failure.
- Settings writes are atomic before publication. Corrupt/unknown-version documents are preserved and block writes; move/repair the file externally and recreate the store to recover. Defaults keep monitoring off. Configuration normalization preserves ordered unique providers, supports empty selection and clamps layout values.
- Successful readings are timestamped and retained only in memory, bound to a SHA-256 fingerprint of the request's credential/account headers. The fingerprint is never logged, persisted or exposed to UI. Same-account transient failures retain dated readings with the upstream stale grace; changed or unavailable credentials clear predecessor data even when the new request fails. Unlike upstream, account readings are not restored from disk: only settings and retry deadlines survive restart, so no unverified previous account is displayed. Auth failures and backoff clear quota values (credentials are not reread during backoff, so account identity cannot be confirmed). No production fixture fallback.

## Checks

`bash scripts/check_usage_monitor.sh` compiles these actual sources with Swift 6 strict concurrency, then runs fixture-based parsers, credential decoders, a temporary WAL SQLite database, mocked URLSession transport and injected store operations. It checks Pi compatibility, fixed official origins, OAuth units/expiry, same-account requests, source precedence and immutable credentials; unavailable sources make zero requests/create no replacement files. It preserves Codex/Cursor/gh file fixtures and rejects reintroduced Keychain entry points in production source or the compiled module's imported symbols. `UsageGoogleChecks.swift` verifies a fresh anonymous gate for every network GET, every source, HTTP/DNS/TLS/timeout/cancellation failures, loss of connectivity before optional requests, recovery, visible cached state and DeepSeek's complete exemption. `PiLocalSpendChecks.swift` adds isolated local-cost fixtures: Decimal totals, rolling 7/30-day cutoffs and local-midnight/DST boundaries, actual-model attribution, CC Switch reference-price goldens, the four gateway ID shapes with missing prices, configured/actual-model precedence, pricing/scan diagnostics, fork deduplication, file mutations, bounded reads, cancellation, auth-file bypass and old-backoff removal. It never reads real provider credentials, home data, Keychain or the network. No XCTest/Xcode installation required.

After `INSTALL=0 bash scripts/build_app.sh`, run `bash scripts/check_usage_ui.sh`. It separately compiles the original Foundation sources in `Tests/CodeNotchReference` and compares identical fixture inputs: 65 quota-window cases, account statistics, 30-day buckets, resets, percentages, pace, reset text, 123 scheduling/event/rollover decisions and 24 activity-tail cases. It then runs strict Swift 6 presentation checks and native AppKit fixtures (lazy hover content, timeline release on close/removal and fresh reopen, inactive-panel hover and native mouse-down/up icon clicks, per-source refresh/rapid-click deduplication/feedback, Reduce Motion and disabled clicks, light/dark/minimum-size settings, error/empty states, actual controller show/hide and stop/restart, display geometry). It prints a temporary screenshot directory. These are programmatic fixture checks, not live-account, hardware-pointer, VoiceOver or physical display-hotplug validation; the real app is not launched.

For an explicitly requested real-account comparison, `VITAPET_VERIFY_LIVE_CODEX=1 bash scripts/check_usage_ui.sh` adds one three-endpoint, same-response parser comparison. It requires an already saved Codex opt-in/selection, honors saved backoff, does not refresh expired credentials, keeps response bodies only in memory, and prints only comparison outcomes. This is separate from the native fixture screenshots and does not prove hardware interaction or the installed CodeNotch app's rendered state.

The public API is in `UsageModels.swift`, `UsageMonitorStore.swift` and the Codex presentation models/helpers. `UsageBarSettings.normalize()` applies the same layout bounds in callers/tests. `previewReadings` is deterministic, isolated-preview-only data and is never read by production polling.
